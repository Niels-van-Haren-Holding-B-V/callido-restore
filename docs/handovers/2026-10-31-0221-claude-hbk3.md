**Done (all on main, released as v0.2.0 together with hbk-2's H21 daemon PR #63)**
* **PR #59, first-run findings from the v0.1.0 DMG** (relayed by hbk-2 from Niels's test):
  * Google Drive sign-in: the Drive step, its status line and the connect job's message say that a browser window opens and
    that the user closes it at rclone's "Success! All done" page and comes back; the new connection is added to the
    "connection I already set up" list and selected; a spinner with the job stage ("Signing in…", "Listing your Drive…")
    sits next to the greyed Next button.
  * The wizard no longer gets stuck after the browser round-trip: `waitJob()`/`sleepOrWake()` in `static/index.html` replace
    the setTimeout-driven polling (WebKit throttles timers while the user is in the browser, and an exception inside the timer
    left the Promise unsettled). Polls that fail are retried, the sleep ends on `visibilitychange`/`focus`, an unknown job ends
    the wait, Next is always re-enabled, and a job that finished while the user was away advances the wizard. `pollJob()` and
    the NAS connect use the same helper.
  * Browse step: backups found in a folder get "Use <name>" buttons, a click on a backup row selects it, Next from the folder
    above picks the single detected backup (several: asks to click one); the "use anyway" prompt only remains when nothing is
    found and is reworded. The scan problem for a wrong folder explains it ("not a Hyper Backup root … remove and add again").
  * `/api/rclone/ls` makes one `lsjson --max-depth 1` call and splits on `IsDir` (was two calls, about 1.3 s each on Drive).
  * Busy indicators on every rclone wait in the browse and target steps (dimmed list + spinner, click guards).
  * Opening a backup is a job: `/api/open?job=1` runs `Backup(src, log)` with step messages ("Listing the backup folder…",
    "Listing shares i/n…", "Reading the version list…", …); `openSource()` waits with `waitJob` and shows the step; then a plain
    GET `/api/open` returns the info. `tests/restore/test_scan_progress.py`.
  * `@AppConfig` is shown as "Application settings (DSM, not restorable here)", greyed, excluded from the restore tree.
  * Parked nits from #56/#45: `JOB_ID.fullmatch` with a hex-only class, the connect handler reads `body` directly. The Drive
    client secret still goes to `rclone config create` in argv (rclone has no stdin/env route that lands in rclone.conf).
* **PR #61 (replaces #60), UI responsiveness** (Niels: "each action is tied to rclone, it feels slow"):
  * `api()`/`post()` go through `track()`: an in-flight counter shows a header activity pill after 200 ms with a text from
    `activityLabel(endpoint, params)` ("Listing nas shares…", "Loading from Google Drive…", "Counting files…") and disables the
    triggering button; `/api/remotes` results are cached 30 s client-side (cleared after a new connection).
  * `toast()` / `toastError()` (bottom-right, stacking) replace every `alert()`; `confirm()` stays for real decisions.
  * `addBasket()` / `removeBasket()` keep `S.basket` as the single source of truth and emit `basketchange`; toasts with
    "View selection" and "Undo"; the always-visible "Restore selection · N items · size" header button (pulses on change) opens
    a panel with per-item counts/sizes (`/api/restore_count` per item, cached), ✕ per row, "Clear all" with Undo, "Continue to
    restore". The `+` buttons in Folders/Search and the Folders-tab button are state toggles (`bkState()`/`paintBk()`:
    "✓ In restore" removes on click, "✓ Included" via a parent explains the tree, "+ partly").
  * Restore step 3 says "Not started · N GB of index files to download" (from `index_bytes`/`index_bytes_local` of
    `/api/pool`, added by #63) instead of "0% · 0 of 0 blocks".
